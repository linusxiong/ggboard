# Backend review — 2026-10-22

Adversarial correctness and security review of the merged Go backend (branch `w3/be-review`, base `97d3a07`).
Every package under `internal/` was read: auth/passport/MFA/account, orders/payments/gateways, node APIs/online/traffic,
subscription (formats, engine, rule sets), admin/user APIs and their services, importer, static, db, scheduler, mail.

**Result: 5 high, 17 medium, 24 low findings fixed** (each with a regression test unless noted), plus documented accepted
risks. Gates after the fixes: `gofmt -l` empty, `go vet` clean, `golangci-lint` 0 issues (it reported 1 goimports issue
before), `go test ./... -race` green. `govulncheck`: 13 reachable **standard-library** vulnerabilities in go1.27.1 (fixed in
1.27.2/1.27.3, see L24); no reachable module vulnerability.

Regression tests are named `TestReview*` (files `review_test.go`, plus `index_review_test.go`, `review_ext_test.go` and two
additions to existing files: `traffic_test.go`, `scheduler_test.go`). Line numbers are after the fix.

## Accepted risks (deliberately left)

- **`admin_mfa_required` checks that a factor is configured, not that it was used**: an admin with only a passkey signs in
  with the password alone and passes `AdminGate`. Matches the contract. Recommendation: an `amr` claim in the JWT
  (`pwd`/`otp`/`passkey`) and require `otp|passkey` in `AdminGate`.
- **No re-authentication to enable TOTP or add a passkey** (contract), and `/forgot` does not clear TOTP: a stolen session can
  add a persistent passkey. Passkey login uses `userVerification: preferred`. Recommendation: password re-check for factor
  enrolment, `required` UV for usernameless login.
- **Plan `capacity_limit` counts active holders only** (pending orders not reserved): concurrent buyers can oversell. Same as
  Xboard and docs/PAYMENTS.md.
- **Commission withdraw ticket + transfer** can pay the same commission twice if staff pay the ticketed amount. Xboard
  behaviour; staff process.
- **BTCPay** webhooks are not bound to a payment uuid and the invoice currency is not compared with the site currency;
  invoices come from our own store via an authenticated API call. Two ggboard payments on one store raise spurious alerts.
- **`HandleNotify` checks `payment_id`/handling on a snapshot**; a re-checkout racing a notify can store the second
  method's handling fee (no underpayment).
- **Last-admin guard** is check-then-act on PostgreSQL/MySQL (needs two admins demoting each other simultaneously).
- **Generated-users CSV password cell** is not `csvSafe`-prefixed: the password must be shown verbatim; only an
  admin-chosen password could start with `=`.
- **MySQL case-insensitive collation** still applies to coupon/invite codes (users' email/token are exact-matched in Go).
  Recommendation for new installs: `utf8mb4_bin` on code/token columns.
- **`frontend.dir`** is indexed at boot: restart after redeploying the SPA directory.
- **Node token holders are trusted**: alive entries for arbitrary uids are kept until TTL (bounded per user, not per node).
- **Subscription `mirror` override** is restricted to catalog ids / `0` / `1`; a custom https prefix only changes the
  user's own config.
- **Settings `email_template` and `frontend_*`** are stored but never read (documented in docs/API.md); exposing
  `frontend_*` via `/guest/config` is an open item (the SPA must sanitize `frontend_footer_html`).
- `golang.org/x/crypto/openpgp` advisory (GO-2026-5932): not imported, no fix exists.
- Nits left: `DecodeProfile` ignores trailing bytes; the preview's "unknown client" branch is unreachable;
  `If-None-Match: *` is not honoured.
